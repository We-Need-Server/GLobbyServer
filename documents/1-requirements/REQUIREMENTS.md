# REQUIREMENTS.md

## 1. 프로젝트 개요 (Project Overview)
본 문서는 게임 사용자를 위한 회원가입 및 로그인 기능을 제공하는 로비 서버(GLobbyServer)의 요구사항을 정의한다.
이 서버는 두 가지 주요 인터페이스를 가진다.
1.  **웹 인터페이스**: 일반 사용자가 브라우저를 통해 직접 회원가입하고 로그인할 수 있는 서버 사이드 렌더링(SSR) 방식의 정적 웹 페이지.
2.  **gRPC 인터페이스**: 다른 내부 마이크로서비스들이 사용자의 인증 토큰을 검증하고 관리할 수 있는 고성능 내부 API.

## 2. 주요 기능 요구사항 (Functional Requirements)

| ID      | 기능명                       | 설명                                                                                                                                                             |
| :------ | :--------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **FR-001** | **사용자 회원가입**        | 사용자는 웹 페이지를 통해 아이디와 비밀번호를 입력하여 계정을 생성할 수 있다. 서버는 비밀번호를 해싱하여 데이터베이스에 저장해야 한다.                                |
| **FR-002** | **사용자 로그인**          | 사용자는 아이디와 비밀번호로 로그인할 수 있다. 로그인 성공 시, 서버는 JWT(Access/Refresh) 토큰을 발급하여 `HttpOnly` 쿠키에 저장하고 사용자를 프로필 페이지로 리다이렉트한다. |
| **FR-003** | **사용자 로그아웃**        | 사용자는 로그아웃할 수 있다. 서버는 관련 쿠키를 만료시키고 사용자를 로그인 페이지로 리다이렉트한다.                                                                |
| **FR-004** | **인증된 사용자 정보 조회**    | 로그인한 사용자는 자신의 프로필 페이지에 접근할 수 있다. 이 페이지는 인증 미들웨어에 의해 보호되어야 한다.                                                          |
| **FR-005** | **gRPC 기반 토큰 유효성 검사** | 내부 마이크로서비스는 gRPC를 통해 전달받은 액세스 토큰의 유효성을 인증 서버에 질의하고, 결과를 (유효 여부, 사용자 ID)를 응답받을 수 있다.                      |
| **FR-006** | **gRPC 기반 토큰 갱신**      | 내부 마이크로서비스는 gRPC를 통해 리프레시 토큰을 전달하여 새로운 액세스 토큰을 발급받을 수 있다.                                                                   |

## 3. 비기능 요구사항 (Non-Functional Requirements)

| ID      | 구분       | 설명                                                                                                                            |
| :------ | :--------- | :------------------------------------------------------------------------------------------------------------------------------ |
| **NFR-001** | **보안**     | - 모든 비밀번호는 `bcrypt`와 같은 강력한 단방향 해시 함수를 사용하여 저장한다.<br>- 웹 인증에는 `HttpOnly`, `Secure` 속성을 가진 쿠키를 사용한다.<br>- JWT 비밀 키 등 민감한 정보는 설정 파일을 통해 외부에서 주입한다. |
| **NFR-002** | **성능**     | 내부 서비스 간 통신은 오버헤드가 적은 gRPC를 사용하여 빠른 응답 시간을 보장한다.                                                   |
| **NFR-003** | **안정성**   | - 서버는 종료 시그널 수신 시, 진행 중인 요청을 안전하게 마무리하고 종료(Graceful Shutdown)하는 기능을 갖추어야 한다.<br>- 데이터베이스 등 외부 서비스 연결 실패 시를 대비한 재시도 로직을 고려한다. |
| **NFR-004** | **관리 용이성** | - 모든 로그는 구조화된 형식(JSON)으로 출력하여 추적 및 분석이 용이해야 한다.<br>- 서버 포트, DB 정보 등 주요 설정은 코드와 분리되어 관리되어야 한다. |

## 4. 제약사항 (Constraints)
- 백엔드 시스템은 반드시 `Go` 언어를 사용하여 개발한다.
- 프론트엔드는 React, Vue 등 별도의 SPA 프레임워크를 사용하지 않고, Go 서버가 직접 렌더링하는 정적 HTML 페이지만으로 구성한다.
