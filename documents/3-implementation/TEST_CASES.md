# TEST CASES

본 문서는 GLobbyServer의 각 기능에 대한 테스트 케이스를 명세합니다. 모든 기능은 정상, 예외, 엣지 케이스로 나누어 검증합니다.

---

### 1. 사용자 회원가입 (FR-001)

| 테스트 ID | 시나리오                     | 테스트 단계                                                                                              | 예상 결과                                                                                             | 구분 |
| :-------- | :--------------------------- | :------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------- | :--- |
| **TC-001**  | 정상적인 회원가입          | 1. `/register` 페이지에 GET 요청.<br>2. 유효한 아이디/비밀번호를 입력하고 `POST /register` 요청. | 1. `200 OK` 상태 코드와 함께 회원가입 페이지가 렌더링된다.<br>2. `302 Found` 상태 코드로 응답하며 `/` (로그인 페이지)로 리다이렉트된다.<br>3. 데이터베이스 `users` 테이블에 새로운 레코드가 생성되고, 비밀번호는 해시된 값으로 저장된다. | 정상 |
| **TC-002**  | 중복된 아이디로 가입 시도      | 1. 이미 존재하는 아이디를 사용하여 `POST /register` 요청.                                              | 1. `409 Conflict` 상태 코드로 응답하거나, `200 OK` 응답과 함께 "이미 존재하는 아이디입니다."와 같은 에러 메시지를 포함한 회원가입 페이지가 렌더링된다. | 예외 |
| **TC-003**  | 유효하지 않은 입력값 (짧은 비밀번호) | 1. 8자 미만의 짧은 비밀번호를 사용하여 `POST /register` 요청.                                      | 1. `400 Bad Request` 상태 코드로 응답하거나, `200 OK` 응답과 함께 "비밀번호는 8자 이상이어야 합니다."와 같은 검증 에러 메시지를 포함한 회원가입 페이지가 렌더링된다. | 예외 |
| **TC-004**  | 빈 값으로 가입 시도          | 1. 아이디 또는 비밀번호 필드를 비워둔 채 `POST /register` 요청.                                          | 1. `400 Bad Request` 상태 코드로 응답하거나, `200 OK` 응답과 함께 "아이디와 비밀번호를 모두 입력해주세요."와 같은 에러 메시지를 포함한 회원가입 페이지가 렌더링된다. | 예외 |

### 2. 사용자 로그인 및 로그아웃 (FR-002, FR-003)

| 테스트 ID | 시나리오                     | 테스트 단계                                                                                              | 예상 결과                                                                                                                              | 구분 |
| :-------- | :--------------------------- | :------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------- | :--- |
| **TC-005**  | 정상적인 로그인              | 1. 가입된 사용자의 아이디/비밀번호로 `POST /login` 요청.                                                 | 1. `302 Found` 상태 코드로 응답하며 `/profile`로 리다이렉트된다.<br>2. 응답 헤더에 `access_token`과 `refresh_token`을 담은 `HttpOnly`, `Secure`, `SameSite=Strict` 속성의 `Set-Cookie`가 포함된다. | 정상 |
| **TC-006**  | 존재하지 않는 아이디로 로그인    | 1. 데이터베이스에 없는 아이디로 `POST /login` 요청.                                                      | 1. `401 Unauthorized` 상태 코드로 응답하거나, 에러 메시지를 포함한 로그인 페이지가 렌더링된다.                                              | 예외 |
| **TC-007**  | 틀린 비밀번호로 로그인         | 1. 가입된 사용자의 아이디와 틀린 비밀번호로 `POST /login` 요청.                                          | 1. `401 Unauthorized` 상태 코드로 응답하거나, 에러 메시지를 포함한 로그인 페이지가 렌더링된다.                                              | 예외 |
| **TC-008**  | 인증된 사용자의 프로필 접근    | 1. 로그인 성공 후 받은 쿠키를 포함하여 `/profile` 페이지에 GET 요청.                                     | 1. `200 OK` 상태 코드와 함께 사용자 정보가 포함된 프로필 페이지가 렌더링된다.                                                           | 정상 |
| **TC-009**  | 인증되지 않은 사용자의 프로필 접근 | 1. 로그인 쿠키가 없는 상태에서 `/profile` 페이지에 GET 요청.                                             | 1. `302 Found` 상태 코드로 응답하며 `/` (로그인 페이지)로 리다이렉트된다.                                                              | 예외 |
| **TC-010**  | 정상적인 로그아웃            | 1. 로그인된 상태에서 `POST /logout` 요청.                                                                | 1. `302 Found` 상태 코드로 응답하며 `/`로 리다이렉트된다.<br>2. 응답 헤더에 토큰 쿠키를 즉시 만료시키는 `Set-Cookie`가 포함된다. | 정상 |

### 3. gRPC - 토큰 유효성 검사 (FR-005)

| 테스트 ID | 시나리오                 | 테스트 단계                                                                   | 예상 결과                                                                                                     | 구분 |
| :-------- | :----------------------- | :---------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------ | :--- |
| **TC-011**  | 유효한 Access Token 검증   | 1. 유효한 Access Token으로 `AuthService.ValidateToken` RPC 호출.              | 1. `ValidateTokenResponse` 메시지를 받는다.<br>2. `is_valid` 필드는 `true`이고, `user_id` 필드는 해당 사용자의 ID이다.   | 정상 |
| **TC-012**  | 만료된 Access Token 검증   | 1. 만료된 Access Token으로 `AuthService.ValidateToken` RPC 호출.              | 1. `ValidateTokenResponse` 메시지를 받는다.<br>2. `is_valid` 필드는 `false`이고, `user_id`는 비어있다.             | 예외 |
| **TC-013**  | 잘못된 서명의 토큰 검증    | 1. 서명이 위조되거나 잘못된 토큰으로 `AuthService.ValidateToken` RPC 호출.      | 1. `Unauthenticated` gRPC 상태 코드를 포함한 에러를 받는다.                                                   | 예외 |
| **TC-014**  | 빈 토큰으로 검증 시도      | 1. 빈 문자열 토큰으로 `AuthService.ValidateToken` RPC 호출.                     | 1. `InvalidArgument` gRPC 상태 코드를 포함한 에러를 받는다.                                                   | 엣지 |

### 4. gRPC - 토큰 갱신 (FR-006)

| 테스트 ID | 시나리오                           | 테스트 단계                                                                                              | 예상 결과                                                                                                              | 구분 |
| :-------- | :--------------------------------- | :------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------- | :--- |
| **TC-015**  | 유효한 Refresh Token으로 토큰 갱신   | 1. 유효한 Refresh Token으로 `AuthService.RefreshToken` RPC 호출.                                         | 1. `RefreshTokenResponse` 메시지를 받는다.<br>2. `access_token` 필드에 새로운 유효한 Access Token이 포함된다.               | 정상 |
| **TC-016**  | 만료된 Refresh Token으로 갱신 시도   | 1. 만료된 Refresh Token으로 `AuthService.RefreshToken` RPC 호출.                                         | 1. `Unauthenticated` gRPC 상태 코드를 포함한 에러를 받는다.                                                            | 예외 |
| **TC-017**  | 유효하지 않은 Refresh Token으로 갱신 | 1. 데이터베이스에 없거나(예: 사용자가 모든 기기에서 로그아웃) 위조된 Refresh Token으로 RPC 호출. | 1. `Unauthenticated` gRPC 상태 코드를 포함한 에러를 받는다.                                                            | 예외 |
| **TC-018**  | Access Token으로 갱신 시도         | 1. Access Token을 Refresh Token으로 착각하여 `AuthService.RefreshToken` RPC 호출.                      | 1. `InvalidArgument` 또는 `Unauthenticated` gRPC 상태 코드를 포함한 에러를 받는다. (토큰의 용도가 잘못되었음을 나타냄) | 예외 |

### 5. Redis - Refresh Token 관리 (New)

| 테스트 ID | 시나리오                           | 테스트 단계                                                                                              | 예상 결과                                                                                                              | 구분 |
| :-------- | :--------------------------------- | :------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------- | :--- |
| **TC-019**  | Refresh Token Redis 저장 확인       | 1. 로그인 성공 후 Refresh Token 발급.<br>2. Redis에서 `GET refresh_token:{hash}` 실행.                   | 1. User ID가 반환된다.<br>2. TTL이 약 7일(604800초)로 설정되어 있다.                                                      | 정상 |
| **TC-020**  | Refresh Token TTL 만료 확인         | 1. Refresh Token 저장 시 TTL을 1초로 설정.<br>2. 2초 대기 후 Redis 조회.                                | 1. Redis에서 해당 키가 존재하지 않는다 (자동 삭제됨).                                                                    | 정상 |
| **TC-021**  | 로그아웃 시 Redis 토큰 삭제 확인     | 1. 로그인 후 Refresh Token 발급.<br>2. 로그아웃 API 호출.<br>3. Redis에서 해당 토큰 조회.               | 1. Redis에서 해당 토큰이 삭제되어 조회 결과가 `nil`이다.                                                                 | 정상 |
| **TC-022**  | 다중 기기 로그인 - Token Set 확인    | 1. 동일 사용자로 2번 로그인 (다른 브라우저/기기 시뮬레이션).<br>2. Redis `SMEMBERS user_tokens:{user_id}` 실행. | 1. 2개의 서로 다른 token hash가 Set에 저장되어 있다.                                                                     | 정상 |
| **TC-023**  | 중복 Refresh Token 저장 방지        | 1. 동일한 Refresh Token을 2번 저장 시도.                                                                  | 1. Redis `SET` 명령은 덮어쓰기되므로 문제없이 저장된다.<br>2. 중복 토큰 사용은 애플리케이션 레벨에서 방지해야 함.            | 엣지 |
| **TC-024**  | 존재하지 않는 Refresh Token 조회    | 1. Redis에 없는 token hash로 `GET refresh_token:{invalid_hash}` 실행.                                    | 1. `nil` 값이 반환되어 인증 실패 처리된다.                                                                               | 예외 |
| **TC-025**  | 전체 로그아웃 (모든 기기)           | 1. 동일 사용자로 3개 기기 로그인.<br>2. 전체 로그아웃 API 호출.<br>3. 각 Refresh Token으로 갱신 시도.    | 1. Redis에서 해당 사용자의 모든 token이 삭제된다.<br>2. 모든 갱신 시도가 실패한다.                                        | 정상 |
